Trust is derived, never stored

folk has no confidence scores. A fact's trustworthiness is a tier, computed at read time from three things the journal already records honestly: who asserted it (actor), what kind of event asserted it (kind), and what backs it (evidence). There is nothing to tune, so there is nothing to drift.

The four tiers, precisely

TierComes fromWhat earns it
curated Person files A human wrote it. The top tier is not "very confident" — it is a different kind of thing: a judgment, not a measurement.
observed kind: observation, mechanical actor (extract:v1, import:media-library:v1) Determinism. A mechanical actor is a versioned tool with no LLM anywhere in its path — that property, not accuracy claims, is what earns the tier. Anything with an LLM in the loop must write as agent:<name> instead.
stated kind: promotion, evidence: stated A verbatim quote plus a msg: pointer, and lint proves both: the quote must appear in the cited message (5-word shingle match) and the fact's subject must be that message's speaker. Testimony about a third party doesn't qualify — reframe with the speaker as subject, or demote to interpreted.
interpreted kind: promotion, evidence: interpreted An inference. Honest about being one: the note is a summary, and the src pointer is the audit trail to what it was inferred from.

Why no numbers?

Confidence scores look rigorous and behave badly. Someone has to pick them; nobody can audit them; they silently encode one model's calibration at one moment; and every downstream consumer starts thresholding against them, which turns an arbitrary number into load-bearing infrastructure. folk's alternative is categorical and honest: the tier tells you what kind of backing a fact has, and the src pointer lets you check the backing yourself. A quote either appears in the message or it doesn't. A tool either has an LLM in its path or it doesn't.

Invariant 5

No conf numbers. Trust is a tier derived at read time from actor + kind + evidence. Bedrock-level facts are only ever suggestions — only the human edits Bedrock.

Bedrock: identity is not a fact level, it's an ownership level

Promotions carry a level: core for ordinary durable facts, bedrock for identity-level claims ("this is a defining moment", "this is who they are"). The asymmetry is total: a lint-clean core promotion lands in the index at its evidence tier and is immediately queryable; a bedrock promotion never becomes an index fact, no matter how clean. Replay surfaces it as a suggestion, folk review presents it, and if the human accepts, the fact enters the person file — the only authority for Bedrock — with the exact diff shown first. Machines can notice who someone might be; only a person decides.

Derived-at-read-time has teeth

Because the tier is a projection, not a stored value, several things follow for free:

  • Retroactive correctness. If a tier rule is refined (as the subject-must-be-speaker rule was), the next rebuild reclassifies history correctly. No backfill migration, no stale scores.
  • The tier can't be forged separately from the evidence. There is no field to set — to claim stated, an event must carry a quote that survives shingle verification. The tier is a consequence.
  • Downstream ranking stays deterministic. folk show groups its profile by tier; surfacing uses the tier order as one of its four rankers. Nothing anywhere needs a threshold.

One honest limitation, by design: the tier speaks about provenance, not sincerity. A manipulative statement in a real conversation is still genuinely stated — the containment for that lives in the review boundary, not in the tier system.
