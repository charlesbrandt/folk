Reading the records, and the optional dashboard

folk's views are commands that read the three records and print a result. None of them calls a model, and none of them writes. The optional web dashboard is a second front end over the same library. It adds a small number of write paths, each going through a path folk already uses, and it lives in its own directory that can be deleted without touching the command line.

The read-only view family

Five commands read the records and nothing else. Each one is deterministic when it is given a fixed time, and none of them imports a model client.

  • folk show <name> prints one person or Locus: tags, archetype, voice, appearance, checkpoint names, associations, and defining moments, read from the person file. It is a summary, so checkpoint contents need folk render.
  • folk graph emits a Mermaid diagram over the derived index. --person draws an ego graph (depth 2 by default), --locus draws a Locus's cast, and --context filters by tag. If the graph would exceed the node limit, it prints a warning on stderr and no diagram, so the output stays readable.
  • folk surface answers "given this Locus or these people, what facts from outside this context bear on them?" It ranks triples with four orders (tier, recency, recurrence, and how connected the far entity is), fuses them with reciprocal rank fusion, and returns at most --budget items, 12 by default. Superseded records and candidate-tier records never qualify. Stale records drop to the bottom rather than out of the list. Each item carries a one-line reason that names the shared entity.
  • folk focus applies the same fusion to containers, which are people and Loci, not triples. It answers "which containers are worth attention right now?" It can be scoped by --locus, by --person, or by --collection.
  • folk agenda lists the next occurrence of each date in every person file's ## Dates section, soonest first, within a window of --within days (30 by default). A recurring month-and-day is rolled forward against the current date. The result for a date already passed this year is next year's, and a February 29 in a non-leap year is treated as March 1.

Two properties hold across the family. surface and agenda read the wall clock when --now is omitted, because staleness and the date window depend on it, so a reproducible run passes --now and then gives byte-identical output. focus does not read the clock. Where a command offers --json (surface, focus, agenda), that form is the machine-readable output for prompt assembly or a dashboard. A consumer that wants a briefing reads the ranked list. It does not get a second ranking of its own.

The web dashboard

The dashboard lives in web/. It has its own requirements file, and it imports folk as a library rather than calling the command line. The folk package itself has no dependency on it, so deleting web/ leaves every command in the table above working. It is local-first and single-user. It is a write surface, so it is not meant to be exposed to other people.

Its read endpoints serve the same data as the commands above: the collection list, the people grid, a tiered person profile, ego and Locus graphs, the Locus list, a Locus profile, a Locus timeline, the agenda, and the focus ranking. The Home view shows agenda and focus panels. A Locus page has a Map view, drawn from the cast graph, and a Timeline view, drawn from its dated events.

Its write endpoints are two. The review endpoint accepts or rejects one queue item at a time, because the request shape takes a single item and never a list, so a batch accept is not possible. The edit endpoint writes a person-file section, limited to an allowlist that includes the appearance section. A preview call shows the diff first, and the commit call re-derives that diff on the server rather than trusting the client's copy. The commit stages only the one file it changed, runs as one git commit, and then rebuilds the index.

Two things are deferred on purpose. The Corkboard view is planned for a later version, and the Studio view is set aside, possibly for good. Several things are out of scope for this version: push notifications, which belong to the agent layer that reads folk agenda --json; multi-user access and any network exposure; real-time collaborative editing; any model-derived ranking; and showing a reference image, which waits on the reference-image design. The web tests need the web dependencies installed, so they cannot run in an environment that has only the core package.

What the views do not do

  • No view calls a model. The ranking is the four orders and the fusion, and the reasons are mechanical.
  • No view writes to the index. Only folk index --rebuild does, and a rebuild is deterministic.
  • No view opens an image. folk reads no image file anywhere in its code.
