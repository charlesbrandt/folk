folk — remember the people you know

folk is a UNIX-philosophy CLI for remembering people: real ones, colleagues, fictional characters, authors, musicians — and the connections between them. It is a memory substrate that agents write into and read from, without ever being trusted to decide what is true.

The tool is small, but the conceptual load is real. Almost every design choice in folk falls out of a handful of ideas that repeat everywhere once you see them. This site exists to make those ideas visible.

The one-paragraph version

There are three records, each authoritative for exactly one thing: person files (markdown, git) hold what the human curated; the journal (append-only NDJSON) holds what happened; the index is a disposable cache derived from the other two by a deterministic rebuild. Agents and LLMs may propose facts, but every proposal passes a mechanical lint and queues for human review — nothing becomes durable without a person deciding. Trust is not a number anyone tunes; it is a tier derived at read time from who asserted a fact and how. And the whole thing is plain files: greppable, diffable, stdlib-only, no daemon, no lock-in.

Five ideas that explain everything else

Idea 1 — one authority per record

Person files, journal, index: each is the single authority for one kind of truth. Nothing is ever authoritative in two places, so nothing can drift or conflict about what is real. Three records →

Idea 2 — trust is derived, never stored

There are no confidence numbers anywhere. A fact's trust tier — curated observed stated interpreted — is computed at read time from who wrote it and how. Trust tiers →

Idea 3 — the past is append-only

Journal segments are never edited. A wrong event is corrected by a later event; even canonicalization (slug aliases) is a projection applied at rebuild, with the journal untouched. One human-only exception exists, for privacy: redaction. The journal →

Idea 4 — LLM proposes, script disposes

Exactly one place in the whole system has an LLM: writing promotion proposals. Everything that decides — lint, rebuild, tier derivation, ranking — is a deterministic script. Run it twice, get byte-identical output. Promotion & review →

Idea 5 — domains never muddy each other

Real people, fictional characters, authors, musicians live in physically separate collections — config, never code. Cross-domain links are explicit graph edges (appears_in, created_by), not shared files. Domains & loci →

Philosophy, compressed

  • Agency: the system suggests, you decide. Only a human edits Bedrock.
  • Files over databases: markdown and NDJSON — greppable, jq-able, git-trackable. No lock-in.
  • Intentional curation, not algorithmic dumping: remembering someone is a choice, not a scrape.
  • Perennial: Python stdlib only, zero daemons, zero dependencies. The tool should still run in twenty years.
