Where folk is, and where it's going

folk is built in phases. The foundation, Phase 1, and Phase 2 — the Archivist — are implemented and tested. Phase 4 is partly built as an optional web dashboard; Phase 3 and the rest of Phase 4 remain direction, deliberately undesigned until their prerequisites are real.

Phase 1 shipped: folk render

The first generated persona view: folk render --format soul <person> turns a person file into a SOUL.md persona file by pure, deterministic templating — no LLM, byte-identical on unchanged input, tested by literally diffing two runs. Crucially, v1 reads only the person file: nothing observed, stated, or interpreted leaks into a system prompt, because deciding which machine-tier facts belong there is a ranking problem that belongs to the Archivist. The rendered file opens with a marker comment — do not hand-edit; edit the person file and re-render — a convention, not a lock, like everything else in folk.

Phase 2: the Archivist, in three deterministic pieces

The Archivist is the part of the architecture that manages memory over time — measuring what promotion produces, aging what's no longer reinforced, and surfacing what another context should know. All three specs share one discipline: no model call anywhere. The Archivist ranks, lenses, and proposes with pure functions; the only LLM in folk remains the promotion step.

7 · Measure first: the eval harness

Before building on promotion's output, measure it. The harness scores stored or live promotion runs against human-labeled reference sets on the TRUSTMEM triad: coverage (nothing important omitted), faithfulness (nothing hallucinated — ungraded candidates are reported for human grading, never auto-failed), and preservation (adding a session never mutates what was already true — checked byte-for-byte against a rebuild). No LLM judge: an LLM grading an LLM would reintroduce exactly the unmeasurability this removes. The regression rule is simply that no metric decreases against a recorded baseline.

8 · Two ways a true fact stops mattering

A fact nobody has mentioned in a year is stale; a fact contradicted by a newer same-slot fact is superseded. The consolidation literature's warning is that these must not share a mechanism — so folk gives them opposite ones:

Both mechanisms are driven by per-predicate attributes in vocab.json (stability, functional) — config, human-classified, proposed through the existing review queue when rebuild notices conflicting values on an unclassified predicate. One human decision per predicate; no new event kinds, no schema change.

9 · folk surface: the piece RAG doesn't do

Not "retrieve text matching a query" but "notice that something established in another context bears on this one." A session starts; folk surface --locus X --person Y answers: given this focus, what small set of cross-context facts should this session know? In-slice facts never appear — the session already has them by construction. Surfacing is definitionally about what lies just outside.

And the posture holds to the end: surface proposes; nothing links, nothing writes. The command is read-only — no journal events, no auto-linking. A surfaced connection that deserves durability travels the existing paths: the human curates it, or conversation re-mentions it and promotion proposes it. Which also means surfacing adds no memory-poisoning surface of its own: it can only re-rank what already passed the journal's containment.

Read views: focus and agenda

folk focus ranks people and Loci rather than facts, through the same RRF engine as folk surface: it answers what is worth attending to, not what to remember. folk agenda lists the next dated events (birthdays, anniversaries) from each person file's ## Dates section, soonest first, within a look-ahead window. Both are read-only, and both are deterministic given an injected --now: no model call, no writes.

Not built yet

  • Phase 3 — Cast: multiple agent identities backed by folk. Undesigned.
  • Phase 4 — GUI: partly built. The optional web/ dashboard (FastAPI and Svelte, with its own dependencies outside the stdlib-only core) has the collection browser, tiered person pages, ego-graph, Locus map and timeline, a Home panel with focus and agenda, and a write side for person-file edits and the review queue. Corkboard and Studio are not built, and the design doc (docs/design/web-ui.md) is still a draft.
  • Embeddings, prose synthesis, mid-conversation surfacing, --with-core: each named, each parked, each with a written condition for when to revisit. Restraint is a feature here — every deferred item is a place the system stayed testable.
