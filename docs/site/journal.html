The journal: what happened, forever

The journal is folk's event log — the append-only record of what actually happened: who said what, what a tool observed, what an LLM proposed, what a human decided. It is the only record machines may write into, and the discipline around it is strict precisely because of that.

Anatomy of an event

One event per line, NDJSON. Here is a promotion event — the richest kind — annotated:

{"v": 1, "id": "8c1f0a2b9d3e", "ts": "2026-07-14T03:11:02Z",
 "actor": "agent:assistant-main", "kind": "promotion",
 "evidence": "stated", "level": "core",
 "s": "person:sam", "p": "works_at", "o": "org:studio-b",
 "src": "msg:20260514_025200_91059e71#12",
 "session": "conv:20260514_025200_91059e71",
 "when": "2026-05",
 "note": "\"I've been at Studio B since May\" — current job"}
  • s / p / o — the claim itself, as a subject–predicate–object triple. Slugs are lowercase, hyphenated, type-prefixed (person:, work:, topic:, locus:); predicates come from vocab.json or arrive with a one-line p_def as a coinage proposal.
  • actor — who wrote it: human, agent:<name>, or a mechanical tool version like extract:v1. This is one of the three inputs to the trust tier.
  • evidence + src + note — the backing. For stated, the note must contain the verbatim quote and lint verifies it appears in the message src points at, spoken by the fact's subject.
  • level — core (ordinary durable fact) or bedrock (identity-level → only ever a suggestion to the human).
  • id — 12 hex chars of sha256 over ts|actor|s|p|o, computed at append time. Recomputable, so lint verifies it — and it's what later review/redaction events point at with ref.
  • ts vs when — when the event was recorded vs the fact's own time anchor. "Started at Studio B in May" recorded in July: ts is July, when is May.

The five kinds

KindWritten byWhat it is
sessionextract step (mechanical)One per processed conversation — marks it present, carries conversation-level facts and the counterparty list review tooling filters on.
observationdeterministic tools onlyMechanical record: participants, utterances, adapter exports (a track played, a search run). No LLM, ever — that's what earns observed.
promotionan LLM, as agent:<name>A proposal that a fact deserves an index triple, with evidence, level, and a lint-verifiable trail. The only event kind an LLM produces, anywhere in folk.
reviewhuman, alwaysA decision: verdict: accept | reject on the event ref points at. Decisions are themselves journal events — the decision history is auditable and replayable.
redactionhuman, alwaysThe one sanctioned exception to "nothing is forgotten", for privacy. Replay expunges the ref'd event entirely — triples and drill-down — which is stronger than a reject.

Append-only, corrected forward

Segments are never edited. Not for typos, not for retractions, not for canonicalization. Every correction is a later event that refers to the earlier one — so the record of being wrong, and of noticing, is itself part of the record.

Roots and segments: where journal files live

There is no single global journal. A journal root is a directory of segments scoped to one collection — roots follow domain, not writer — so an agent conversing with you writes to personal's root while a roleplaying character writes to characters', and the domains never lump together. Registration is config, two ways: automatically (a collection directory containing journal/) or explicitly (~/.config/folk/journal-roots, for roots that live next to their producer, like an external adapter's own database directory).

Readers are forgiving; writers are strict

The schema is frozen and lint enforces it hard at write time — but readers follow a deliberately weak-schema policy: unknown fields are ignored, unknown kind or v values are skipped with a warning, never a crash. That asymmetry is cheap insurance from the event-sourcing literature: it means v: 2 events could coexist with v: 1 readers during a migration instead of forcing a flag-day rewrite of every consumer.

Invariant 6

Lint before append. Any programmatic append runs the lint first; hard failures quarantine the whole batch for folk review — nothing partial ever lands.

What lint checks: schema shape per kind, id recomputation, slug rules, resolvable src pointers, the 5-word shingle quote match, speaker attribution (a stated fact's subject must be the cited message's speaker), and duplicate triples within a promotion batch. Coined predicates and near-duplicate entity slugs are soft output — proposals for review, not errors. Lint is the executable form of docs/design/journal-schema.md; if they disagree, one of them is a bug.
