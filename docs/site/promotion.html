How a conversation becomes memory

Every night on the server, folk promote turns quiescent conversations into journal events: a mechanical extract that always succeeds, an LLM proposal step that is never trusted, a deterministic lint that gates everything, and a human review queue where durability is actually decided. LLM proposes; script disposes.

Why the shape is exactly this

  • Extract runs first and always. The mechanical record — who participated, what was said, with msg: pointers — cannot fail on content, so it lands even when the LLM step doesn't. History is never held hostage by a model.
  • The LLM writes proposals into a buffer, not events into the journal. Its output only becomes journal events after passing the full lint against the actual transcript: schema, verifiable quotes, speaker attribution, slug rules, duplicates.
  • All-or-nothing appends. One hard lint error quarantines the session's entire promotion batch. A half-appended batch would be a record whose gaps are invisible; a quarantined batch is a visible object a human can triage in folk review.
  • Soft findings flow, hard failures stop. A coined predicate with a definition, or a near-duplicate entity slug, is a proposal — it appends fine and queues for review. Only verifiable violations (a quote that isn't in the message, a subject who didn't speak it) are hard.
  • Sources are pluggable. The first agent wired up is the first transcript source, not a structural requirement. An adapter's whole contract is: ordered, speaker-attributed messages with stable 0-based indices — that stability is what the entire msg: pointer system (and therefore quote verification) rests on.

The review queue: where durability is decided

The journal design lets agents write freely because nothing they write becomes authoritative without a human decision. That only works if pending decisions are visible and cheap to make — so everything that needs one queues in a single place:

Queue itemAccepting it means
Vocab proposal — a coined predicate with its p_defThe predicate enters vocab.json (which stays the vocabulary's single authority; the review event is the audit record).
Bedrock suggestion — level: bedrock promotionThe fact enters the person file — diff shown, interactively confirmed, every time. The tool is a typist, not an author.
Entity-resolution proposal — near-duplicate slugsAn alias lands in vocab.json; the next rebuild merges the slugs as a projection. The journal is untouched.
Lint failure — a quarantined batchUsually: inspect and discard. Occasionally: re-run promotion. Never: hand-edit the events into acceptability.

Two properties make the queue trustworthy. It is derived, never stored: an item is pending iff it exists in the journal (or quarantine) and no review event resolves it — there is no queue file to corrupt or drift. And decisions are journal events (kind: review, verdict, ref), append-only like everything else, so the history of deciding is itself replayable.

The containment boundary

Here is the uncomfortable fact the design takes seriously: memory-poisoning attacks (MINJA, arXiv:2503.03704) succeed through ordinary conversation — crafted text that really was said. The journal records it honestly, src lint passes honestly, and the trust tier is truthful about provenance while silent about manipulation. No amount of provenance machinery can catch a lie delivered in person.

This is why the counterparty field exists on session events, and why the rule attached to it is written as a security property: promotions from a session involving someone other than you are always reviewed one at a time. Batch flows are reserved for self-directed sessions, where the only person who could have poisoned the well is you.

Measured, not vibed

The promotion job's quality is the one place an LLM's judgment matters, so Phase 2 starts by making it measurable: the TRUSTMEM eval harness scores promotion output against human-labeled references on coverage, faithfulness, and preservation — with no LLM judge anywhere in the scoring path. Until those numbers exist, "did the prompt change help?" is an anecdote; after, it's a diff against a recorded baseline.
